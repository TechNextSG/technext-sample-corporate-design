Key takeaways

  • Every Odoo upgrade starts with an upgraded test database. You test there, not on your live system.
  • How you get that test copy depends on hosting: the database manager on Odoo Online, a staging branch on Odoo.sh, or Odoo's upgrade script on-premise.
  • Test the changes first: Field Service moved into Planning, payroll work entries are gone, account groups became parent accounts, and AI features now use paid credits.
  • Custom modules must be ready for Odoo 20 before the database can be upgraded. Once production is upgraded, there is no going back.

Odoo 20 is out, and many owners are asking the same thing: when should we move, and what could break? The honest answer is that it depends on what you use and where Odoo runs. The good news is that Odoo's own upgrade process is built around testing first. If you follow it, there are few surprises on go-live day.

This checklist is based on Odoo's upgrade documentation and the Odoo 20 release notes. For the full list of what is new, read our Odoo 20 release notes summary.

How an Odoo upgrade works, in four steps

Odoo's documentation describes the same process for every database:

  1. Get an upgraded test database. Odoo upgrades a copy of your data to the new version.
  2. Upgrade your custom modules. Any custom code must be ported to Odoo 20.
  3. Test, and report issues. Your team works in the test copy. Problems with the upgrade itself go back to Odoo.
  4. Upgrade production. Only when the test copy works do you plan the live upgrade.

Odoo 19 to 20 migration: Online, Odoo.sh or on-premise

The steps are the same everywhere. How you start them is not. If you are not sure which one you are on, our guide to Odoo Online vs Odoo.sh vs on-premise explains the difference.

  • Odoo Online. In the database manager, choose your database, click Manage, then Upgrade. Pick the target version and keep the purpose set to Test. Odoo emails you when the test copy is ready.
  • Odoo.sh. The upgrade runs from your project. Odoo sends the latest daily backup of production to its upgrade platform, and the upgraded copy lands on a staging branch. Your custom modules must be ready for Odoo 20 on that branch.
  • On-premise. You run Odoo's upgrade script from the server that hosts the database. It sends the database to upgrade.odoo.com and brings back an upgraded copy. Your team installs the new Odoo version and handles the server side.

The Odoo 20 upgrade checklist

Work through these in order. Each one is a reason we have seen upgrades slip.

  1. List what you use. Write down every app, Studio change, custom module and integration. This list becomes your test plan.
  2. Check what moved or went away in Odoo 20. The standalone Field Service app is discontinued and its features now sit in Planning. Payroll work entries, and the Planning-to-Payroll link, are removed. Account groups are replaced by parent accounts. If you rely on any of these, test them first.
  3. Get custom modules ready. Odoo's documentation is clear: a database with custom modules cannot be upgraded until those modules exist for the target version. Odoo's upgrade service covers standard apps and Studio customisations, not custom code without a maintenance contract.
  4. Request the test database. Use the route for your hosting type above.
  5. Know what is switched off in the test copy. Odoo disables scheduled actions and outgoing mail, sets payment providers and delivery carriers to test mode, and turns off bank synchronisation. So nothing from your test reaches a customer or a bank. It also means you must check those features on purpose.
  6. Run a normal week. Have the people who use Odoo daily repeat their usual work in the test copy: quotes, orders, deliveries, bills, payments.
  7. Close a test month. Ask finance to reconcile and run their reports in the test copy, using parent accounts instead of account groups.
  8. Decide on AI. Odoo's release notes say all AI features now need credits bought through IAP. Choose which ones to switch on and set a budget before people start using them.
  9. Rehearse, then go live. Odoo suggests a rehearsal the day before, a quiet time for the upgrade, and no edits to production while it runs. The database is unavailable during the upgrade, and once it is done you cannot revert to the old version.

Should you upgrade to Odoo 20 now?

If you only use standard apps on Odoo Online, the test copy is quick to get, and the main work is your own checks. If you have custom modules, integrations or Payroll and Field Service in daily use, plan it like a small project. Either way, nothing goes live until the test copy has survived a normal week and a test month-end.

Common questions about upgrading to Odoo 20

How do I upgrade from Odoo 19 to Odoo 20? {{icon:chevron}}

Request an upgraded test database first: through the database manager on Odoo Online, through a staging branch on Odoo.sh, or with Odoo's upgrade script on-premise. Upgrade any custom modules, test thoroughly, then plan the production upgrade.

Can I undo an Odoo 20 upgrade? {{icon:chevron}}

No. Odoo's documentation says that once the production upgrade is complete, you cannot revert to the previous version. That is why all testing happens on a copy first.

Will my custom modules work in Odoo 20? {{icon:chevron}}

Not automatically. Custom modules must be ported to Odoo 20 before the database can be upgraded. Odoo's upgrade service covers standard apps and Studio customisations, but not custom code unless it is under a maintenance contract.

Will the test database send emails to my customers? {{icon:chevron}}

No. In the upgraded test database, Odoo disables outgoing mail servers and scheduled actions, puts payment providers and delivery carriers in test mode, and turns off bank synchronisation.
